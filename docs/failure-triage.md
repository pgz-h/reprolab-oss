# 按失败现象处理

从 0.19.0a4 开始，项目结果页会把需要处理的记录归为可浏览的现象组。无需模型账号，归类只读取已保存结果。

## 桌面流程

1. 在结果页选择现象组，例如“变更后 · 测试准备 · 导入异常 · 3 项”。选择新组会清除先前的搜索和状态筛选，先展示整组。
2. 查看影响数量和处理建议。“检查项目环境”使用当前对应会话；“查看两版日志”展示保存日志；“定位代表项”定位组内具体测试，继续使用现有修复说明和验收入口。
3. “复制本组诊断”复制整组测试 ID、异常、归类依据及建议，不发送到外部服务。
4. 修改原项目后，点击“复查本组（N 项）”。它冻结当前工作区，发现、核对并运行整组；搜索隐藏的成员仍包括在按钮标明的 N 项内。测试变化或发现不完整时会停在可继续的新会话。
5. 在新报告中“与上次比较”，未复查的其他测试单列，不能算作已解决。

搜索、结果状态和现象组共同决定显示范围。“显示 M / N 项 · 本组共 K 项”区分可见结果、报告范围和整组范围；“清除筛选”恢复全部结果。

## 归类边界

归类依据是版本、实际记录的阶段、异常类型和保存的消息。相同异常不证明共同根因；同一测试可以同时属于基线、变更后或不同阶段的组，所以组数量和组内数量不能直接相加作为唯一失败数。

测试主体失败、准备失败、清理失败、导入异常、跳过与 xfail 分别说明。缺少阶段时不猜测为测试主体失败；缺少异常细节的独立断言不会被粗略合并。

收集失败、整版超时、取消和不完整进程记录按整版情况说明。总超时不是每个测试都超时。已通过的所选测试不会仅因整版收集问题而被归为失败；无法关联到某项的整版问题会显示 0 个已关联测试，并保留日志入口。

现象组不修改原始报告、回归状态或证据。严格确认目标修复仍使用现有案例验收。

## 离线报告与 CLI

新生成的离线 HTML 包含现象概览，可选择现象筛选逐项结果。旧 HTML 保持原样，桌面和 CLI 可对可校验的旧项目报告做只读归类。

```sh
reprolab project diagnose /path/to/report --output /path/to/new-diagnostics.json

reprolab project recheck /path/to/report \
  --sessions /path/to/sessions --output /path/to/reports \
  --test 'tests/test_feature.py::test_case[one]' \
  --test 'tests/test_feature.py::test_case[two]'
```

`diagnose` 先校验证据，只读生成归类结果；命令成功不代表测试通过，原结果在 `recorded_status` 中。JSON 包含来源报告指纹、完整组成员和原始分类统计。

`recheck --test` 只能引用来源报告实际选择的 ID，保持来源报告的选择顺序，与 `--scope attention` 互斥。空清单、未知 ID 不会自动变成全部测试。
