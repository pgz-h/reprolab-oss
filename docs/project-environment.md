# 项目环境接入

从项目检查的“检查环境”进入。窗口分为“检查与使用”“pytest 插件”“运行变量”“运行差异”“准备新环境”五个页面，Python 选择位于上方，当前检查状态和“使用已检查环境”位于底部。

## 检查与使用

Python 下拉列表直接列出原项目的 `.venv`、`venv` 和 `env`，从冻结会话进入也使用原仓库查找。列出候选不会切换或启动解释器，当前选择及虚拟环境链接路径保持不变。声明、依赖组和运行配置仍以当前检查来源为准，不能把原项目的新配置当成已用于旧快照。

检查结果区分已知问题与尚不能静态确认的声明：缺包、版本不符、Python／pytest 信息不可用或无效 ReproLab pytest 配置需要先处理；动态依赖、私有来源或其他未解析声明可在核对需处理项后，勾选“已核对未确认的依赖声明，继续使用现有环境”。此时采用已有 Python，不安装依赖，也不将 `review` 改成 `ready`。切换 Python、依赖组、重新检查或重开窗口都需要重新核对；自动准备新环境的支持边界不变。

从发现问题处进入时，还可点击“使用环境并重新发现”。该操作沿用当前固定源码，重新执行测试收集，完成后停在测试范围，不运行测试主体。只点击“使用已检查／已核对环境”则只采用选择；关闭窗口不自动继续。如果插件或运行变量声明尚未应用、原项目配置尚未刷新，会就地说明并停止，先完成配置再继续。本机变量值仍只在当前应用会话提供，不保存到设置。

项目基础依赖始终包含。应用还会列出 `pyproject.toml` 中的 `[dependency-groups]` 和 `[project.optional-dependencies]`，可勾选需要的测试或开发组。“选择推荐测试组”会加入名为 test、tests 或 testing 的组，其他选择保留；不会自动加入全部 dev 或工具组。

勾选后自动重新读取所选可信 Python 的安装版本，检查不会导入项目或加载 pytest 插件。组支持规范化名称和 `include-group` 引用；循环、缺失、未支持条目或不支持的依赖来源会明确显示需复核。未选择组中的扩展内容不提前求值。规则依据 [PyPA Dependency Groups 规范](https://packaging.python.org/en/latest/specifications/dependency-groups/)。

“只看需处理项”保留缺少、版本不符或不能确认的声明。“复制环境摘要”复制所选组和待处理依赖，便于交给开发者处理。项目页会记住明确选择的组，关闭窗口或重开应用后可继续使用。

## pytest 插件

插件页列出当前配置及所选 Python 的插件入口元数据。可勾选插件、手动添加模块／入口名并选择导入方式，生成 `[tool.reprolab.pytest]` 草稿。勾选和预览不会加载插件，也不会写入文件。

从项目工作台进入时，可以选择“预览并应用到原项目…”。先查看原项目 `pyproject.toml` 的实际差异，明确点击“应用以上修改”后才保存。其他配置和注释保留；配置文件、权限发生变化时要求重新预览，不能修改链接文件或冻结快照。复制配置的原入口仍可使用。

原始文件与修改记录保存在应用工作目录的 `project-config-edits` 中，不进入被测 Git 项目。可以选择“撤销上次配置修改…”查看恢复差异，确认后恢复原始字节与权限；若保存之后又有其他编辑，停止撤销。关闭并重开环境窗口后仍可使用撤销记录。

当前检查若使用冻结快照，保存配置后点击“刷新工作区使用配置”，窗口会关闭并沿用固定基线另存新会话，带入原测试选择。该操作不自动发现或执行测试；准备好后继续发现、核对范围和运行。原快照与报告保留。

已安装表示找到相应入口元数据；项目内表示静态找到声明模块。两者都不保证实际导入或兼容性，仍由后续运行确认。无法确认、信息不可用和入口冲突分别显示，已有声明不被静默删除。列表使用 Python 的 [importlib.metadata](https://docs.python.org/3/library/importlib.metadata.html) 读取信息，不调用插件的 load 方法。

切换依赖组重新检查时，会保留正在准备的插件配置。切换 Python 会保留插件与导入方式草稿，但清除旧环境检查结果；重新检查相应环境后才能使用。完整执行规则见[插件配置](pytest-plugins.md)。

## 运行差异

此页依据当前检查来源，说明实际使用的插件与导入方式、项目／fixture 的保留规则、被清空的 `addopts` 和允许继承的基础环境变量。

静态列出 pytest.ini、pyproject.toml 等文件中检测到的附加参数声明，不推断多个配置文件的优先级。未声明的终端自定义变量不会自动带入。“运行变量”页可以声明普通值和本机变量名称；本页说明实际规则。PYTHONPATH 等执行控制变量仍不能覆盖。

CLI `environment inspect` 的 `execution_settings` 字段包含同一份静态信息。读取不会导入项目、执行测试或加载插件。

## 准备新环境

选择独立 Python 和项目之外的新目录，点击“预览准备计划”。预览包含所选组及展开后的安装声明；只有明确点击创建才联网安装。

修改依赖组、解释器、目录或项目声明会使旧计划失效，需要重新预览。创建前重新核对完整计划，安装后仍按相同的依赖组检查。现有环境不会被覆盖或自动修改。

当前仅从公开 PyPI 安装具名 wheel 依赖，不安装项目本身、不执行项目构建后端。Poetry 专属配置、动态依赖、私有索引、VCS／路径依赖和完整传递依赖锁定不在此自动准备范围。

## CLI

```sh
reprolab environment inspect /path/to/project \
  --python /path/to/project-env/bin/python --group test --extra speed

reprolab environment plan /path/to/project /path/to/new-env \
  --python /path/to/base-python --group test --extra speed \
  --output /path/to/environment-plan.json

reprolab environment create /path/to/environment-plan.json
```

`--group` 对应 dependency-groups，`--extra` 对应 optional-dependencies，均可重复。省略时只检查基础声明和 pytest，不自动选择开发组。旧版本保存的环境计划需重新预览。

## 复用项目环境选择

桌面会按原仓库路径记住上次使用的解释器与时限。新建检查时可点击“使用上次环境与时限”；这一步只填写界面，不启动解释器或执行代码。解释器原路径保留，不将虚拟环境符号链接解析为系统 Python。环境已移动或失效时，需要重新选择。

发现失败后，可以直接从错误区打开环境检查。修改解释器后仍保留当前固定源码，重新发现以核对新环境下的测试清单。

运行变量的桌面步骤、CLI 配置、敏感值边界和重放规则见[运行变量指南](runtime-variables.md)。


## 普通子进程与已安装的项目副本

0.19.0a13 起，每版执行向普通子 Python 进程提供本版快照的 src／根目录，并让 PATH 优先使用所选 Python 的命令目录。避免子进程因工作目录变化而退回 editable 安装的原项目；不继承用户任意 PYTHONPATH，不自动加载插件。显式 -I／-E、重建环境或自定义导入器仍须单独核对。需要 Python 子进程的项目请选择独立 Python，应用内置执行器不是通用 Python 命令。真实样本、配置差异和限制见[适配记录](real-project-adaptation.md)。
