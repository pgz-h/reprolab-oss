# 执行边界与可靠保存（v0.13.0）

## 只运行选中的一个测试

预检仍不导入或收集项目。实际运行时，pytest 完成收集后必须恰好选中一个测试；在单项执行入口再次核对，以防项目钩子改变选择。零个或多个测试会在 fixture / 测试主体之前停止，报告保留实际数量、目标和原因。参数化测试需选择具体的 `[参数标识]`。合法的 collection hook 将选择缩小到一个测试仍可使用。

收集本身会导入测试和 conftest，项目钩子本身也会运行。这不是安全沙箱，也不承诺阻止可信项目代码在导入/钩子内自行产生副作用。测试只在临时源码副本运行；after 的同一测试覆盖两版临时副本，保存的原始快照不改变。

worker 记录必须包含正确的阶段字段，setup、call、teardown 必须属于同一测试，并与选中目标一致。缺记录不能推断为零测试；错误或不完整记录保持无法验收。

## 输入准备期间发生变化

准备前记录两份源码的目录清单、内容指纹和普通文件的读写执行权限，复制后核对保存快照和当前输入；案例与测试字节也要一致。新增/删除/改写文件或目录、文件权限变化、测试/案例变化、不可读目录会停止本次验收。请停止修改输入后重新运行。

这是前后内容一致性检查，不是文件系统事务，也不防御恶意并发修改后恢复原字节。准备完成后，运行使用固定快照；原始文件后续修改不影响已固定的这次运行。

## 完整保存后才有结论

保存时重新核对源码、测试、重放配置、实际 worker 事件和日志。先保存可读 HTML 和证据指纹，最后通过同目录临时文件、flush/fsync 和原子替换写入 report.json；CLI、批次和桌面共享这个完成边界。保存失败时不发布新的最终结论，不覆盖旧报告。

每次运行目录内的 operation.json 记录准备、旧版、新版、保存阶段及已经返回的运行记录。它不是验收报告：没有 report.json 的目录属于未完成材料。保存完成前，过程状态可为 awaiting_report；有效 report.json 优先于过程记录，不再追加可能失败的成功后写入。失败时界面显示阶段、已返回记录和材料路径；重启扫描也会提示未完成或取消的材料。

异常退出或强制终止宿主时可能留下过程文件或 HTML；仅有 HTML 不构成完整交付。最终 JSON 是目录列表采用的发布标记，分享前仍应执行“检查证据”。不承诺断电下的文件系统事务或自动续写报告。

schema 4 报告的 persistence 字段保存 HTML、两版日志、两版事件、重放案例和测试指纹；源码保留原有目录/内容指纹，并额外记录普通文件权限指纹。回放案例还会绑定源码、测试和权限指纹，执行前核对它们。工作区案例、故障试运行和 AI 计划的新固定输入也记录文件权限。检查证据会发现这些文件缺失、内容或已记录的权限发生变化。旧报告、案例和计划仍可读取，但没有记录的权限不能追溯核对；相关提醒会出现在新报告和 AI 解读预览中。桌面历史状态可能在升级后显示为需重新验收。权限记录不覆盖目录权限、所有者、ACL、扩展属性或特殊权限位。校验值不是身份认证，不能防止有人同时重写证据和校验值。

新建的工作区案例和试运行案例包含新的权限字段，v0.17.1 及更早版本可能拒绝读取；旧版即使能够打开新 AI 计划，也不会核对新增的权限指纹。请使用本开发版或后续兼容版本打开新材料。

## 真实项目适配

本轮使用 python-dotenv 官方 1.0.0 / 1.0.1 源码包，核对 PyPI SHA-256 并保留原 BSD 许可证。选择修复后已有的 `tests/test_zip_imports.py::test_load_dotenv_gracefully_handles_zip_imports_when_no_env_file`，读取各版本 setup.cfg 和 tests/conftest.py，依赖 pytest、click、sh 放在独立环境。

旧版实际触发 OSError（Starting path not found），新版通过同一测试。来源为 [官方历史 PR #456](https://github.com/theskumar/python-dotenv/pull/456)，完整下载清单及本机证据路径见本版验证记录。这是多文件项目接入和历史复现，不能表述成新 Bug、完整项目测试通过或上游采用。

该项目会根据 sys.frozen 改变行为，因此历史案例使用完整外部 Python 环境；打包应用的内置运行时不保证与普通 Python 的所有行为相同。原有选择外部 Python 的操作即可完成，无须新配置页面。
