# 项目回归工作台

项目工作台将一次项目改动保存为可重开的会话：固定 Git 基线和另一提交或当前工作区，查看改动，实际发现参数化测试，选择多个 node ID，然后把同一份目标测试交给前后版本执行。它适合回答“这批改动有没有让所选测试出现新增失败”。

报告的通过结论只覆盖本次所选测试。项目回归通过不能证明目标问题已完整修复，也不能证明全部项目功能正确。需要先声明旧版应出现什么错误、再验证新版修复时，继续使用现有单项验收或 AI 项目验收计划。

## 从选中失败处理并验收

结果详情先展示完整测试 ID、两版实际状态与异常摘要。测试主体失败时可“准备修复说明”，或在修复源码后“验收当前修复”；受阻项显示对应诊断和环境入口。准备只校验证据并另存固定输入，正式执行仍须单独点击。新案例的故障版来自原报告真正失败的变更后快照，原报告曾通过的基线仅作背景。候选测试变化有差异提示，默认采用原报告保存的完整检查。

操作与来源、文本范围、取消／重试、重开及 CLI 边界见[失败修复指南](failure-repair.md)。

## 桌面使用

常用测试可以在“测试选择”中保存为命名方案，例如“冒烟检查”或“支付相关”。同一仓库的新会话会列出这些方案；应用前按当前真实发现清单核对，缺失目标先说明，原勾选不会被静默丢弃。选择方案只保存目标，不执行测试或携带验收结论。

1. 从“概览”选择“检查一次项目改动”，选择本地 Git 仓库、基线版本、对比版本与 Python 环境。默认比较最近一次提交（HEAD）和当前未提交改动；修复已经提交时，应选择实际的改动前后提交。准备会话时会冻结当前内容，之后编辑原仓库不会改变该会话。
2. 标题与问题说明可选。点击“准备并发现测试”连续冻结和收集，进入测试范围；若要先查看差异，可用“仅冻结版本”，之后再发现。
3. 收集会加载可信项目和 conftest，获得包含参数化用例的精确 pytest node ID。完成后先核对勾选范围，推荐仅用于帮助选择；发现失败或取消时已准备的快照保留。
4. 选择要执行的测试并运行。一次选择 1–2000 个测试，每版各使用一个 pytest 进程。可以取消运行；取消报告保留已完成结果，未完成项保留为受阻。
5. 查看逐项结果、阶段与异常，打开 HTML 报告。需要继续处理时，重开已保存会话，重跑所选项目；每次正式运行产生独立报告。

两版使用对比版本的同一份目标测试文件，同时保留各自的项目配置和 conftest。对于测试文件本身的改动，报告仍保留原始两份源码快照，实际运行使用的共享测试另有指纹记录。

读取仓库时会列出 `.venv`、`venv`、`env` 中已有的 Python 路径供选择，不自动启动或切换。保留虚拟环境的原路径；项目环境与可选标题分开填写，小窗口可以滚动输入区。输入被冻结后，“检查环境”使用固定的变更后源码声明，避免原仓库后续编辑改变检查材料。

填写「发现范围」可在收集开始前指定一个相对目录或 Python 测试文件，例如 `tests/unit`。留空使用项目的 pytest 默认范围。范围随会话保存，刷新、复查和重放沿用；如果范围内路径在新快照中已删除，请重新选择范围。页面里的文件／目录筛选用于整理已经发现的测试。

连续键入时，搜索会在短暂停顿后应用。立即点击批量选择会先使用最新查询。搜索和筛选保留已经勾选的测试。下一步提示会明确说明被隐藏的勾选数量，运行按钮显示总项数。要只运行筛选结果，应先“清空”，再“选中可见”。

也可使用“仅选可见”直接替换选择，在文件／目录下拉列表中缩小范围，或从“选择操作”反选可见项、复制 ID、导入和导出 JSON／逐行文本清单。导入清单和应用命名方案都会先显示完整核对窗口：查看匹配项、未找到项和其他可选数量，可搜索、只看缺失项并复制全部缺失 ID。只有点击“采用可用项”才替换勾选，取消保留原选择；不会自动替换改名或缺失目标。选择清单不包含源码、环境或验收结论。

会话的 `desktop-view.json` 保存勾选、搜索、文件范围、筛选和每版限时，不属于源码快照或执行证据。重开同一输入、同一发现环境时恢复，空选择也会保留。开始页可继续上次打开的会话。macOS 使用 ⌘F 定位当前页搜索，其他平台使用系统查找快捷键。

改动列表可筛选测试、Python 源码、配置依赖或文档；结果页的“更多操作”可复制当前筛选摘要、选中测试 ID，或导出 CSV。CSV 仅为摘要，不能替代完整证据。

测试发现失败时，日志会自动展开，操作错误可复制；可以检查或更换 Python，再重新发现，无需重新冻结。结果默认定位新增失败，“定位需处理项”集中展示新增失败、原有失败和受阻项。通过项及完整报告仍保留。

结果详情基于保存的异常、阶段、跳过标记与进程状态提供下一步建议。通过“更多操作”可以复制此项诊断、检查对应会话环境，或查看保存的共享测试代码。预览前核对文件指纹，只读取报告保存材料，不执行测试；大文件只预览前 128 KiB。

在“运行记录”中多选两次运行，点击“对比所选两次运行”。比较先核对各自证据，再显示共同目标的结果变化以及只在一次运行中选中的项目；未重跑项不算作已解决。源码、普通权限或记录的环境元数据不同会明确说明。对比摘要可以复制或导出 JSON，来源报告保持原样。

## 从指定报告发起复查

结果页可明确选择“来源报告全部实际选择”或“仅新增失败／原有失败／受阻”，入口显示项数。“用当前工作区复查”绑定当前显示的具体运行及报告指纹，沿用报告保存的固定基线另存快照；普通顶部刷新继续使用当前勾选。发现和正式运行分别发起。

新报告提供“与上次比较”和重新定位入口。对比核对来源身份与证据，逐项显示实际结果、共享测试文件指纹和本轮执行状态；测试文件变化或指纹未知时单列复核，不计入同一检查转为通过。基线、环境和限时分别提示差异或未知。原 ID 的待核对状态会保存，连续刷新不会把它当作主动清空。

完整步骤、空范围 CLI 语义和购物车验收材料见[从指定报告复查](report-recheck.md)。下述内容中的固定快照重跑仍使用保存的源码。

## 修改项目后的下一轮检查

已冻结会话始终使用原快照。修改原仓库后，直接“重跑失败／受阻”仍会执行旧快照；请点击“刷新当前工作区”，另存本次修改。

刷新会沿用来源会话的固定基线提交、标题、问题和所选 Python，改动后版本改为刷新时的当前工作区。即使仓库的 HEAD 已前进，基线也不会随之移动。新会话记录来源 ID 与指纹，原会话、源码证据和旧报告保留。刷新只准备输入，不自动发现或执行测试；需要更换基线时，展开项目输入重新冻结。

桌面会带入当前勾选，包括主动清空后的空选择。点击“发现测试”后按完整 ID 重新核对：全部匹配时只勾选原选择；有缺失时先不勾选，提示核对，用户可明确采用可用项或手动选择。其他测试不会自动加入。重新发现同一会话的测试时，也保留空选择；若保存的选择出现缺失，会显示同样的核对入口。

HTML 报告的“来源与固定输入”显示刷新来源。旧报告与新报告的比较仍只覆盖实际共同选择的目标，不能把未选或缺失目标当作已修复。只调整环境、不改变源码时，可在原会话重新发现或重跑。

## 命令行

所有项目命令从 `reprolab project` 进入，结果以可读 JSON 输出。错误写入标准错误并返回结构化 `error`，不显示 Python traceback。下面的路径均为示例；`--python` 应指向已经具备项目依赖的解释器。

桌面导出的选择清单可以直接用于 CLI：

```sh
reprolab project run /path/to/project-session \
  --selection-file /path/to/test-selection.json \
  --output /path/to/reports --python /path/to/.venv/bin/python
```

`--selection-file` 与重复的 `--test` 二选一，支持 JSON 的 `selected_tests` 列表、JSON 数组或每行一个完整 node ID 的文本；上限 2000 项、8 MiB。执行时仍在当前真实发现清单中核对，不因清单存在就直接判为通过。

沿用原固定基线，准备当前工作区的下一轮检查：

```sh
reprolab project refresh /path/to/original-session \
  --selection-file /path/to/test-selection.json --output /path/to/project-sessions
reprolab project collect /path/to/new-session --python /path/to/.venv/bin/python
reprolab project selection-check /path/to/new-session
reprolab project run /path/to/new-session --output /path/to/reports
```

`refresh` 返回新会话的 `directory`，后续命令须使用它。`--python` 可替换新会话的环境；省略时沿用原环境。`--selection-file` 或重复 `--test` 指定带入的选择意图；省略时只继承来源会话已有的 `selection_request`，不会猜测最近一次运行或读取桌面偏好。没有继承选择的普通会话仍需显式提供清单以带入原选择。

`selection-check` 只读取已保存发现结果，不启动解释器、收集或测试；也可用 `--selection-file`／`--test` 核对任意清单。输出全部匹配和缺失 ID，未发现、空选择或有缺失时返回退出码 2，完整匹配返回 0；这只是范围核对，不代表测试通过或环境仍可用。发现范围不完整时会另外标记。

新会话的 `run` 默认使用继承选择，有缺失则停止，不自动补选或缩小范围。确认后可以显式传入新的 `--selection-file`／`--test`；空选择不变成全部测试。来源会话和报告始终保留。

只读比较两次保存运行：

```sh
reprolab project compare /path/to/earlier-report /path/to/later-report --output /path/to/new-comparison.json
```

对比不执行项目代码，不生成新的修复验收结论。输出文件应是来源报告目录之外的新文件；省略 `--output` 时只输出 JSON。

准备两个已提交版本：

```sh
reprolab project prepare /path/to/repository \
  --before HEAD~1 --after HEAD \
  --output ./work/project-sessions \
  --python /path/to/.venv/bin/python \
  --title '导出模块回归' \
  --issue '检查导出格式变更对现有行为的影响'
```

冻结当前工作区：

```sh
reprolab project prepare /path/to/repository \
  --before HEAD --working-tree \
  --output ./work/project-sessions
```

`--before` 必填，`--after` 与 `--working-tree` 二选一。`--output` 指定会话的保存根目录，返回 JSON 的 `directory` 是后续命令使用的具体会话目录。准备过程保留原仓库及其未提交修改，不进行 checkout、reset 或 commit。

查看会话并收集实际测试：

```sh
reprolab project show ./work/project-sessions/PROJECT_ID
reprolab project collect ./work/project-sessions/PROJECT_ID \
  --path tests/unit --python /path/to/.venv/bin/python --timeout 120
```

`--path` 接受固定快照内的相对文件或目录。省略时沿用会话已保存的范围，`--default-scope` 恢复 pytest 默认范围。也可用 `project prepare --path` 提前保存发现范围。

`show` 读取记录。`collect` 会执行 pytest 的收集过程，因此会加载项目、配置和 conftest。发现列表最多保存 10000 个 node ID；`truncated: true` 表示列表已截断。静态推荐不能替代这一步的实际收集结果。

明确选择多个测试并运行：

```sh
reprolab project run ./work/project-sessions/PROJECT_ID \
  --output ./outputs/project-runs \
  --test 'tests/test_export.py::test_csv[utf8]' \
  --test 'tests/test_export.py::test_csv[gb18030]' \
  --python /path/to/.venv/bin/python --timeout 120
```

`--test` 可重复。node ID 中的 `[]` 等字符需要按所用 shell 的规则引用。省略显式选择时优先使用会话的继承选择；普通会话没有继承选择时使用已收集测试。仍须满足单次 1–2000 个的选择上限；收集结果超过上限时应明确选择子集。`run` 本身就是执行指令，无需再确认一次。

`--timeout` 是每个版本全部所选测试共用的总超时，默认 120 秒，范围 0.1–3600 秒。它不是每个测试分别享有的时长。解释器、Python、pytest 与环境版本会记录在报告中；工具不会自动安装项目依赖。

## 如何阅读结果

| 逐项状态 | 含义 |
| --- | --- |
| `regression_passed` | 两版均实际通过 |
| `regression_detected` | 旧版通过，新版失败 |
| `baseline_failure` | 两版均失败，属于已有失败 |
| `improved` | 旧版失败，新版通过 |
| `inconclusive` | 其他情况，包括跳过、xfail、fixture 问题、未执行、缺失记录、收集失败或超时 |

全部所选测试均为两版通过或改善，并且两版记录完整、没有收集或执行错误，全局状态才是 `regression_passed`。存在新增失败时为 `regression_detected`；其他未能形成通过结论的情况为 `attention`。用户取消的运行保持 `cancelled`。

HTML 的顶部显示真实选择范围与逐项数量，测试矩阵支持本地搜索和状态筛选。展开每版结果可查看 setup、call、teardown 等阶段及异常；原有失败和受阻项会保留。每版运行卡片列出耗时、退出码、超时、记录完整性、版本、收集错误和日志摘要。文件概览展示记录中的改动文件，差异只展示引擎保存的有界预览；完整文件通过源码快照链接核对。

命令退出码：

| 命令或结果 | 退出码 |
| --- | --- |
| prepare、show、成功的 pack / unpack、重放预览 | `0` |
| collect 的 `collected`、check 的 `consistent` | `0` |
| run / 明确重放的 `regression_passed` | `0` |
| run / 明确重放的 `regression_detected` | `1` |
| 收集失败、不一致、`attention`、`cancelled` 或命令错误 | `2` |

## 核对、导出、导入与明确重放

运行 JSON 中的 `report_dir` 是报告目录；以下命令接受该目录，不接受单独的 `report.html`：

```sh
reprolab project check ./outputs/project-runs/RUN_ID
reprolab project pack ./outputs/project-runs/RUN_ID \
  --output ./exports/project-regression.zip
```

`check` 与 `pack` 核对固定输入和证据，不执行测试。不一致的报告不能通过检查或正常导出。ZIP 应另存到报告目录以外的新路径。导出包含报告、原始日志、事件记录及固定项目输入；分享前可自行检查其中的源码、路径和异常信息。

收到证据 ZIP 后，使用专用导入命令保存到一个尚不存在的新目录：

```sh
reprolab project unpack ./exports/project-regression.zip \
  ./imports/project-regression
```

`unpack` 检查归档路径、文件类型和大小限制，恢复普通文件权限，并核对全部报告证据；它不执行项目代码。成功时返回 `status: imported`，以及绝对路径 `directory`、`report_dir` 和导入说明。使用专用导入命令可保留证据校验所需的权限信息。后续命令使用返回的 `report_dir`；以下示例假定它是 `./imports/project-regression`。

重放默认只预览：

```sh
reprolab project check ./imports/project-regression
reprolab project replay ./imports/project-regression
```

预览显示来源、所选测试、原报告及本次的 Python 和每版限时。重放时默认沿用原报告限时，旧报告缺少限时则使用 120 秒。命令行可用 `--timeout` 覆盖，桌面可在重放对话框调整。明确重放时添加 `--confirm-run`：

```sh
reprolab project replay ./imports/project-regression \
  --confirm-run --output ./outputs/replays \
  --python /path/to/.venv/bin/python --timeout 120
```

重放先检查证据，然后从报告保存的固定输入运行相同选择，产生新的报告。它使用当前选择的本机环境；原记录的版本清单不是可自动重建的依赖锁。`replay` 未指定 `--output` 时使用 `outputs/project-runs`；只做预览不会创建运行报告。

## 保存的内容与边界

项目会话包含 `project.json`、固定输入、改动信息、发现结果和历次运行索引。正式报告以 `report.json` 为结构化结果，`report.html` 是可独立打开的离线视图，旁边保存 `before.log`、`after.log`、两版阶段事件和 `evidence/` 中的固定输入。项目快照位于报告的 `evidence/project/inputs/before/`、`evidence/project/inputs/after/`，会话记录位于 `evidence/project/project.json`。

HTML 不使用远程字体、外部脚本、网络请求或上传；脚本仅用于本地搜索与筛选。日志与证据都使用相对链接，复制或解压后应保留完整目录结构。报告渲染器只使用引擎传入的数据，不重新读取项目源码、日志或环境；取消报告缺失的版本记录会明确显示未执行或未记录。

快照沿用每版最多 5000 条目、100 MiB 的限制；发现结果、项目记录、日志和差异预览都有边界。达到限制或记录不完整时，应按报告提示处理，不能把省略信息理解为通过。源码内容、普通文件权限、目标测试、选择清单及日志事件会绑定记录，但一致性检查不是数字签名或作者身份认证。

仅使用可信代码。pytest 收集、测试、配置、插件及 conftest 都可能执行任意本机代码；固定副本和独立进程不提供安全沙箱。项目工作台不修改原仓库来制造通过结果，也不自动修复代码、安装依赖、提交或发布改动。

取消会保留已经完整返回的版本结果及原始日志。当前版本若未返回完整事件记录，其逐项状态保留受阻，不能据此声称没有执行或已经通过；之后可明确重跑所选项。


## 直接复查与插件配置

结果页“复查修改”可直接完成冻结、发现、核对和执行，遇到范围或检查内容变化时保留新会话供核对；详见[报告复查](report-recheck.md)。需要 pytest 插件的项目可声明共享插件与导入方式，详见[插件配置](pytest-plugins.md)。


## 按现象处理重复失败

结果页可按实际异常和阶段查看现象组、复制整组诊断并只复查该组。状态和搜索仍可进一步筛选，按钮明确显示完整执行范围。新离线报告和 `project diagnose` 共用归类规则，详见[失败归类](failure-triage.md)。


## 逐项进度与中断记录（0.19.0a5）

运行时显示基线／候选版本、已完成数量、当前完整测试 ID、准备／主体／清理阶段及耗时。5 秒没有新事件时显示距最近事件的时间；这不等于进程失去响应，也不是剩余时间预测。结果列表逐项更新，正式结论在两版执行与证据保存后显示。

超时、取消、运行中 Ctrl-C 或进程异常退出后，已经保存的阶段作为“中断前观察”保留，最后执行位置可在桌面和离线报告查看。未完整结束的版本保持受阻；中断前某项通过不计为正式回归通过。尚无阶段记录不证明测试从未执行。

结果页优先显示与所选项对应的处理入口：导入异常检查环境，准备／清理或中断问题查看日志，测试主体失败准备修复说明，通过项查看测试内容。原有修复验收、诊断复制和证据操作继续保留。

CLI 可在 project collect、run、recheck 和明确执行的 replay 中加入 `--progress`。实时进度写到标准错误，标准输出仍为最终 JSON，便于脚本保存与处理。


## 多轮处理记录

结果页的“处理记录”沿精确来源串联多轮报告，并单独汇总连续遗漏的测试。每轮可保存独立本机说明、打开原报告或与上一来源比较。来源不完整时只展示已核对区间；数据不会按标题或时间自动合并。操作、读取上限与只读 CLI 见[报告复查](report-recheck.md)。

## 项目偏好与显示顺序

解释器路径和时限按项目保存在本机设置中，可在新建项目时明确采用；不会进入执行结论或自动替换别的项目设置。基础设置、报告自己的环境记录以及会话选择恢复仍各自保留。

完整结果表优先列出新增失败、受阻与已有失败，随后为改善与两版通过。同类项保持原顺序，原报告、测试执行顺序和 CSV 证据数据不因界面排序重写。
