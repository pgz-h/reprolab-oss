# 预检、结果解释和可靠重跑（v0.12）

## 先检查，再运行

桌面单项验收和批量验收会先做预检。它读取案例配置、源码或 Git 提交清单、测试文件路径、预期故障条件、输出位置和可信 Python 的版本元数据；独立测试语法使用所选解释器解析。预检不会导入待测项目、收集或执行 pytest 测试、创建报告目录或调用模型。

关键检查不通过时，界面显示原因和建议，不执行测试。ready 只表示这些检查通过，不能保证项目所有依赖可导入，也不能保证动态收集恰好一个测试。所选 Python 会被启动读取元数据，因此解释器及环境本身仍须可信。原有单项 CLI verify 保持运行器语义，可先显式执行：

    reprolab preflight /path/to/case.json --python /path/to/env/bin/python --output /path/to/reports --json

预检失败退出码为2；通过为0，不代表 verified。

## 根据真实证据解释结果

新报告记录 pytest 真实异常、测试阶段和收集结果，区分：

- 旧版已经复现声明的故障、新版同一测试通过。
- 旧版也通过、声明故障不匹配、新版测试仍失败。
- 缺少模块或项目依赖、收集失败、无测试/多个测试。
- fixture 准备或清理失败、跳过/xfail、超时。
- 工作进程异常退出或没有返回完整记录。

缺少工作进程记录不能被当作“收集了0个测试”。没有精确证据时保留无法判断。模块名也不等于可直接安装的发行包名，因此不自动安装、不猜测根因或调用AI解释。

诊断只解释真实记录，最终验收仍由原有规则决定。HTML和JSON保存下一步建议；旧报告缺少这些新字段时仍可读取，其已保存结论不会被改写。

## 环境版本与变化

新 report.json 保存所选 Python 的路径、版本、系统/架构、可读取的发行包名称与版本，以及环境指纹。只读 Name/Version，不读取 direct_url、环境变量或模型凭据。虚拟环境路径保留，不解析成系统Python。

桌面再次验收会与最近可用报告比较；重跑批次会与来源批次的报告比较。路径、Python或发行包版本变化会提示，但不会否决用户明确选定的新环境。旧报告缺少环境信息时显示无法比较，不能声称相同。

这不是依赖锁，也不证明所有包可导入或文件内容未变。清单记录环境元数据，不能冒充“本次实际导入的全部依赖”。环境记录随报告和证据包一同交付；当前报告使用 schema 4，仍可读取包含这些记录的旧 schema 3 报告。

## 从批次继续处理

批次完成/取消后，或在报告页选中旧批次时，可以选择：

- “重跑未通过项”：选中未通过、无法验收、取消和未运行项；不重新运行已通过项。
- “继续未完成项”：只选中取消或尚未运行的项。

先展示新清单和环境，明确开始后才执行。可以在新批次窗口选择项目环境。每次创建独立批次，旧汇总和旧证据不改写；新汇总记录来源批次、指纹、模式及原始选择。来源记录或选择被改动时要求重新规划，不默默使用错配清单。

重跑针对原路径的当前案例内容和当前环境；它不是自动修改测试，也不会调整故障条件来追求通过。损坏的旧批次被单独跳过，不影响其他案例或报告刷新。

CLI 默认只显示计划，必须加 --run 才执行：

    reprolab retry /path/to/old-batch --mode not_verified --json
    reprolab retry /path/to/old-batch --mode unfinished --run --python /path/to/env/bin/python --output /path/to/new-reports

新输出目录不能位于旧批次目录内。批次仍最多50项，每项恰好一个测试，单项错误后继续；取消保留已完成项。重跑记录不是作者身份认证，仍只执行可信本地代码。
