# Vitest 项目对比预览

桌面和 CLI 都可以比较两个 Git 版本的 JavaScript 或 TypeScript 测试。选择项目相对路径下的完整测试文件，两版运行对比版本保存的同一份测试文件，各自保留项目配置和锁定依赖。

需要 Node.js、npm 和 v2/v3 `package-lock.json` 中锁定的 Vitest 4。独立 npm 项目可位于 Git 仓库根目录或子目录；npm workspace 成员可使用其上级 workspace 根目录的共享锁文件。基线和候选须使用同一个相对安装根目录和相同布局类型。两版在各自的固定副本里从锁文件目录执行 `npm ci`，安装脚本关闭。使用 `--offline` 时需要提前填充 npm 缓存，可用 `--npm-cache` 指定目录。

workspace 的本地包须在共享锁文件中登记，并位于固定的 npm 根目录内。外部依赖使用带完整性值的 registry 锁定记录。workspace 成员可用相对路径、常见通配符和排除规则声明。当前范围包括标准 npm workspace 链接；需要任意本地链接、安装脚本、花括号展开或扩展 glob 的项目仍需其他运行方式。

## 桌面

1. 打开「项目检查 → Vitest 项目对比」，选择本地 Git 仓库并填写「基线版本」。候选使用当前工作区，或取消勾选「使用当前工作区」后填写候选提交、分支或标签。
2. 「npm 项目目录」默认是仓库根目录 `.`，也可填写 `frontend`。点击「发现并填入」可从候选快照读取 Vitest 配置并填入文件清单，填入后可删减。也可每行填写一个 Git 仓库相对路径，或从当前工作区多选文件。候选版本或配置变化后可重新发现。
3. 默认从本机 PATH 查找 Node 和 npm，使用 npm 默认缓存，允许下载依赖，每版限时 120 秒。展开「运行选项」可指定工具和缓存路径、启用离线安装或调整限时。收起后保留输入，并在入口提示「已调整」。
4. 发现和两版执行各自使用设置的 npm 缓存、离线模式和时限，均包含依赖安装。点击「开始 Vitest 对比」后，两版才会执行所选测试。找不到 Node 或 npm 时，表单会展开并定位到对应路径，选好工具后可用原测试文件重试。运行中可点「取消当前操作」。
5. 对比保存报告后，当前 Vitest 页会滚动到总体判定、报告操作和逐项结果。向上滚动可继续编辑原表单。同一文件下可以看到分别改善和新增失败的用例。点击「打开报告」查看最近保存的 HTML 及执行日志。报告目录沿用桌面「设置」，应位于被测仓库外。

点击当前 Vitest 结果区的「导出证据 ZIP…」，在报告目录之外选择一个新文件名。ZIP 包含本轮两版固定源码、所选测试、结果和执行日志。收到 ZIP 后，可用「项目操作 → 导入项目证据…」校验并查看同一轮结果。

### 重放保存的 Vitest 报告

从「项目操作 → 导入项目证据…」选择 ZIP，或用「项目操作 → 打开项目报告…」选择已保存的 `report.json`。校验通过后会在「Vitest 项目对比」页签定位到结果。点击结果区的「重放…」核对来源、固定版本和所选文件。可直接开始重放，默认从本机 PATH 查找 Node 和 npm，并沿用原报告的离线模式和每版限时。

展开「运行选项」可查看原工具链和限时、指定本机 Node/npm 和缓存路径，以及调整离线模式或限时。收起选项时已输入的值会保留。点击「开始重放」后才会在独立副本里安装依赖和执行测试，新结果另存为报告。留在 Vitest 页时，重放完成后会定位到新结果。取消时仍可查看来源报告。若来源在预览后变化，请重新打开并核对。

「运行选项」里的「检查本机工具」可核对 Node 和 npm 的实际路径、版本及与来源的差异。检查使用所选 Node 所在目录优先的 PATH 查询 npm。版本不同仍可开始重放。依赖安装和离线缓存由正式重放核对。

若结果显示某一版因 npm 离线缓存缺少依赖而未运行测试，点击「调整缓存并重放…」直接展开运行选项。离线安装仍按原报告设置。选择已准备的缓存，或明确关闭离线安装以允许下载，再点击「开始重放」。

### 用当前工作区复查

从当前结果、重新打开的 `report.json` 或导入的证据 ZIP 进入「Vitest 项目对比」。点击「用当前工作区复查…」核对来源、固定基线和完整的所选文件。可用「选择 Git 仓库…」改选本机工作区，再设置本机 Node、npm、离线安装、缓存和每版限时。点击「开始复查」后才会冻结新候选、安装依赖和执行测试。

复查直接复制来源报告的基线内容和权限，所选工作区只作为本轮候选。结果另存为带来源引用的新报告。若所选文件整体缺失，会指出具体路径，请恢复文件或改选工作区。取消后仍可查看来源报告，后台退出后可以重试。

「上一轮候选 → 本轮候选」按文件展开实际用例。同一文件可以同时显示已解决和新增失败。共享测试、Vitest 项目、用例清单、锁文件或已记录的运行条件变化时会标明原因。缺失、跳过、预期失败、重试后通过、执行不完整及旧报告缺少逐用例证据时，相关项保留为「未能复查」。重开新报告时，来源证据仍可核对即可恢复这组结果。

### 按验收计划运行

选好仓库、两版来源和项目目录，点「按验收计划运行…」打开已保存的 Vitest 计划。确认后运行计划所列的用例所在的完整测试文件。完成后可查看每项验收结果，复制 PR 摘要，或调整条件补交回执与稳定性证据。

## 命令行

可用 `--selection-file` 读取 JSON 数组或逐行文本，每项为 Git 仓库相对的测试文件路径。桌面「修复验收」导出的 CI 配置可直接用作输入。

使用 `--list-files` 列出候选配置匹配的测试文件，或用 `--all-files` 从同一次冻结的候选发现全部文件并比较。发现会在独立副本中安装候选依赖、加载 Vitest 配置，然后列出文件。自动比较保存发现日志和清单，重放与复查沿用报告中的实际选择。清单为空、同一文件匹配多个 Vitest 项目、发现项目目录之外的文件或超过 2000 项时，命令返回 `2`。配置使用 `includeSource` 时，请手动选择独立测试文件，以免用候选的实现文件覆盖基线实现。

```sh
reprolab project vitest /path/to/repo --before HEAD --working-tree \
  --project-dir frontend --list-files

reprolab project vitest /path/to/repo --before HEAD --working-tree \
  --project-dir frontend --all-files --output /path/to/reports
```

也可以逐个指定要比较的文件。

```sh
reprolab project vitest /path/to/repo --before HEAD --working-tree \
  --project-dir frontend \
  --file frontend/tests/price.test.ts --file frontend/tests/calc.test.js \
  --output /path/to/reports
```

也可用 `--after` 指定第二个提交。npm 项目在仓库根目录时，可省略 `--project-dir`。`--file` 始终相对于 Git 根目录，且须位于所选 npm 项目内。若 `frontend` 有独立锁文件，就在该目录安装依赖。若它是 npm workspace 成员且使用上级锁文件，就从 workspace 根目录安装，仍在 `frontend` 加载 Vitest 配置并执行测试。返回的 `report_dir` 下有 HTML、JSON、两版日志和固定源码。报告、重放和复查沿用保存的 npm 项目目录和安装根目录。Vitest 会按每版项目配置核对所选文件。文件缺失、收集失败、同一文件属于多个测试配置、两版所属项目不同、测试重名或测试清单变化时，文件列为受阻。能核对范围时，报告按用例比较，同一个文件可以同时显示改善和新增失败。文件汇总保留其中最需要处理的结果，用例统计单独显示。跳过、预期失败、重试后通过或执行不完整的用例保留为受阻或未定。报告内的原始记录保留各测试的名称、状态、异常和可用的重试诊断。旧证据仍按生成时的规则校验，重放时生成当前格式。退出码沿用项目检查的 0（所选范围通过）、1（有新增失败）和 2（需处理或命令未完成）。

```sh
reprolab project check /path/to/report
reprolab project pack /path/to/report --output /path/to/evidence.zip
reprolab project unpack /path/to/evidence.zip /path/to/imported-report
reprolab project replay /path/to/imported-report
reprolab project replay /path/to/imported-report --confirm-run --output /path/to/replayed
```

重放预览可查看原环境和时限。正式重放可用 `--node`、`--npm` 选择本机环境，并用 `--offline` 或 `--online` 切换依赖安装模式。首次运行也可用这两个可执行文件选项指定路径。仅对可信仓库和可信证据发起执行。导出材料包括保存的项目源码和日志。
