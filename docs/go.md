# Go 项目对比预览

桌面和 `reprolab project go` 都使用实际的 `go test -json` 比较基线与候选。需要本机 Go 工具链和两版根目录都有 `go.mod` 的 Git 仓库。每次选择一个包目录和一个或多个顶层测试函数。

## 桌面

1. 打开「项目检查 → Go 项目对比」，选择本地 Git 仓库。在「基线版本」填写提交、分支或标签。候选使用当前工作区，或取消勾选「使用当前工作区」后填写候选版本。
2. 在「包目录」填写相对于仓库根目录的路径，例如 `internal/cart`。根包使用 `.`。点击「发现并填入」，从所选候选版本取得顶层测试清单并填入表单。可以删减清单，也可以手工填写函数名，多个名称用换行或空格分隔。切换候选版本或包后，重新发现可更新清单。
3. 点击「开始 Go 对比」后冻结两版并执行表单中的测试。默认从本机 PATH 查找 Go，测试发现与每版执行各限时 120 秒。展开「运行选项」可指定 Go 路径和调整限时。找不到 Go 时，表单会展开并定位到「Go 路径」。发现或执行期间可点击「取消当前操作」。
4. 对比保存报告后，当前 Go 页会滚动到总体判定、报告操作和逐项结果。向上滚动可继续编辑原表单。点击「打开报告」查看最近一次保存的 Go HTML 报告及执行诊断。报告目录沿用桌面「设置」，应位于被测仓库外。

点击当前 Go 结果区的「导出证据 ZIP…」，在报告目录之外选择一个新文件名。ZIP 包含本轮两版固定源码、所选测试、结果和执行日志。收到 ZIP 后，可用「项目操作 → 导入项目证据…」校验并查看同一轮结果。

### 重放保存的 Go 报告

从「项目操作 → 导入项目证据…」选择 ZIP，或用「项目操作 → 打开项目报告…」选择已保存的 `report.json`。校验通过后会在「Go 项目对比」页签定位到结果。点击结果区的「重放…」核对来源、固定版本、包和测试函数。可直接开始重放，默认从本机 PATH 查找 Go，并沿用原报告的每版限时。

展开「运行选项」可查看原工具链和限时、指定本机 Go 路径及调整限时。点击「检查本机工具」查询实际路径和版本，修改路径后可再次检查。版本不同仍可开始重放。收起选项时已输入的值会保留。依赖和缓存由正式重放核对。

点击「开始重放」后才会运行固定快照里的测试，并将结果另存为新报告。留在 Go 页时，重放完成后会定位到新结果。取消时仍可查看来源报告。若来源在预览后变化，请重新打开并核对。

### 用当前工作区复查

在 Go 结果区点击「用当前工作区复查…」。也可先从「项目操作 → 打开项目报告…」选择旧报告的 `report.json`，或导入证据 ZIP。预览会列出原报告、固定基线、包和完整的所选函数。默认使用报告记录的仓库路径。路径来自其他机器时，可用「选择 Git 仓库…」改选本机工作区，并按需设置本机 Go 路径和本次每版限时。

点击「开始复查」才冻结选定工作区并执行两版。基线直接沿用来源报告内保存的固定快照和权限，候选来自本次冻结的工作区。结果另存为带来源引用的新报告。取消后仍可查看来源报告，后台退出后可重试。若整个包缺少 `*_test.go`，请恢复测试文件或改选包含这些文件的工作区。

结果区分别显示本轮的标准两版报告，以及「上一轮候选 → 本轮候选」逐项结果。两轮候选均有完整的通过或失败记录，且基线、所选范围、共享测试文件和已记录的运行条件一致时，才判为已解决、仍失败、新增失败或继续通过。缺失、跳过或执行不完整的测试保留为「未能复查」。共享测试、Go 工具链、每版限时或平台变化时，界面会标明差异。重新打开新报告时，若仍能核对来源证据，会恢复候选间复查结果。

### 按验收计划运行

选好仓库、两版来源和项目目录，点「按验收计划运行…」打开已保存的 Go 计划。确认后运行计划所列的顶层测试。完成后可查看每项验收结果，复制 PR 摘要，或调整条件补交回执与稳定性证据。

## 命令行

可用 `--selection-file` 读取 JSON 数组或逐行文本，每项为一个顶层 Go 测试函数名。桌面「修复验收」导出的 CI 配置可直接用作输入。

用 `--list-tests` 在终端查看候选包的测试清单，再用 `--test` 选择需要比较的函数。

```sh
reprolab project go /path/to/repo --before HEAD --working-tree \
  --package internal/cart --list-tests

reprolab project go /path/to/repo --before HEAD --working-tree \
  --package internal/cart --test TestCheckout --test TestRefund \
  --output /tmp/reprolab-go
```

在 CI 或本地比较整个包时使用 `--all-tests`。发现和执行使用同一次冻结的候选，报告保存实际选中的函数，重放和复查沿用该清单。

```sh
reprolab project go /path/to/repo --before BASE --after CANDIDATE \
  --package internal/cart --all-tests --output /tmp/reprolab-go
```

发现使用 Go 自身的 `go test -list`，按当前平台和构建条件列出顶层测试。该命令会编译测试二进制，可能运行包初始化和 `TestMain`，请用于可信项目。超时、编译失败、空清单或超过 2000 项均返回退出码 `2`；`--all-tests` 在这些情况下不会生成比较报告。

根包可省略 `--package`。已提交的候选使用 `--after COMMIT`，可用 `--go /path/to/go` 选择工具链。两版在独立副本中使用候选版本所选包的全部 `*_test.go` 文件，各自保留实现、模块依赖和其他文件。报告以顶层函数为单位，包括从原始事件按完整名称匹配的子测试。父测试两版都失败时，子测试由通过转为失败仍触发回归。只在一版观察到的子测试标为受阻。旧版证据仍可按原顶层规则核对。编译失败、跳过、找不到所选函数或执行不完整时，相关结果保留为受阻。退出码与 pytest 项目比较相同。

目前支持根模块中的纯 Go 包。本机需提前缓存依赖，预览以只读模块模式执行，并关闭模块下载、自动工具链下载、CGO 和工作区模式。含 `replace` 的模块和嵌套模块需要其他运行方式。只对可信仓库或证据发起执行。

```sh
reprolab project check /path/to/report
reprolab project pack /path/to/report --output /tmp/go-evidence.zip
reprolab project unpack /tmp/go-evidence.zip /tmp/go-imported
reprolab project replay /tmp/go-imported
reprolab project replay /tmp/go-imported --confirm-run --output /tmp/go-replayed
```

Go 大日志会压缩结构化证据中的输出片段，保留测试启动、完成与失败事件。报告记录省略的输出量，完整日志仍随证据保存。
