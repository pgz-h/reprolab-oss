# 从指定报告复查当前工作区

本页描述当前开发版的报告驱动复查功能。2026-11-04 已开放本地定向运行验收，实际范围见[验证与发布状态](release-readiness.md)。

## 从结果页开始

1. 在“项目检查 → 历史记录”打开你要复查的那一次报告。结果页显示当前会话 ID、运行 ID 和所选项数。同一会话有多次运行时，先明确打开目标运行。
2. 回到原项目修改业务源码。不要修改报告里的固定快照。
3. 点击结果页的“复查修改”，要逐步操作，可在菜单选择“仅准备全部测试的复查”或“仅准备需处理项的复查”。每项显示实际数量，范围来自这份报告。
4. 选定菜单项后，工具核对来源报告并另存当前工作区，沿用报告保存的固定基线。此步只准备新快照。
5. 分别点击“发现测试”、核对范围，再正式运行。新报告保留所选来源会话、运行 ID、报告 SHA-256 和范围方式。
6. 新报告结果页会自动核对绑定的来源报告，直接显示同条件转绿、检查需复核、仍失败和未复查范围。需要逐项依据时点击“查看逐项变化”；“打开来源报告”仍会核对身份和证据后打开原 HTML。

“固定快照：重跑失败／受阻”“固定快照：重跑所选行”以及“重跑这份固定快照…”继续使用保存的源码。顶部普通“刷新当前工作区”继续按当前勾选工作；若当前范围仍在等待核对，会带入待核对的原 ID。

应用会记住你明确打开的运行。重开同一会话优先定位这份运行；找不到时说明原因，不改用标题相似的报告或最近一次运行。报告移动后，可从“更多操作”选择“重新定位当前报告”。

## 结果页的复查进展

复查完成及重新打开复查报告时，应用在后台读取并校验来源与当前证据，不重新执行测试，也不自动打开比较窗口。复查页优先展示跨轮进展；本次逐项结果、筛选、日志与完整报告继续保留，普通首轮报告仍显示两版统计。

“同条件转绿”只计入原先实际失败、现在通过或改善，并且测试及所有已记录条件一致的项目。“检查需复核”包含测试变化、条件变化或条件不足；只复查部分测试也会改变选择及顺序，不据此直接认定同条件恢复。未复查、受阻和未完整执行分别列出，不算已解决。这里的条件一致不代表完整环境冻结，也不替代严格故障复现与修复验收。

核对期间可“停止核对”，已有执行结果保留。来源不可用时显示无法确认进展，直接“重新定位来源”或“重新核对”；定位只更新本机偏好，不改写报告，也不猜测最近一次来源。没有绑定来源的旧报告不会凭空生成进展。

## 三种范围状态

- **未指定继承范围**：没有带入清单。桌面可提供默认推荐／可用勾选，CLI 普通会话延续已有默认选择规则。
- **主动清空**：保存为明确的空列表 `[]`。重开、重新发现、切换环境或刷新后仍为空。正式运行须重新选择 1–2000 项，不自动全选。
- **等待核对**：原完整 ID 有本次未找到项，或发现列表不完整。暂不自动勾选，原 ID 可查看和复制；连续刷新或重开仍保留待核对范围。用户明确采用可用项、手动勾选或主动清空后才改变范围。

“本次未找到”可能来自改名、删除、参数变化、环境或不完整发现，不证明测试已经删除。发现失败时可查看原范围，但不能采用或运行尚未有效发现的目标。改名后的 ID 不会自动代替旧 ID。

CLI 的 `project refresh --selection-file empty.json` 和 `project selection-check --selection-file empty.json` 接受内容为 `[]` 的 JSON 文件，分别保存空意图、返回空范围的只读核对结果。未指定范围与空范围分别输出 `unspecified`／`empty`；尚待发现或确认时为 `pending`。空范围只读核对退出码为 2，正式 `project run` 拒绝空范围。

## 比较中的判断

| 展示 | 判断 |
| --- | --- |
| 相同已记录条件下转为通过／改善 | 共同完整 ID、共享测试及已记录比较条件一致，前次实际失败，本次通过／改善 |
| 检查条件已变化／不完整 | 保留本轮实际通过，单列需复核，不计入相同条件下恢复 |
| 测试文件已变化，需复核 | 共同 ID 的共享测试文件 SHA-256 不同，保留两次实际结果，但不计入同一检查转为通过 |
| 测试文件指纹未知，需复核 | 旧报告缺少可选指纹信息，保留实际结果，不猜测测试相同 |
| 未复查（仅前次选中） | 原 ID 不在本轮实际选择中，不作为已解决 |
| 仅本次选中 | 本轮新增选择，单独列出 |
| 本轮未完整执行／受阻／仍失败 | 分别显示未执行、跳过或 fixture 等受阻，以及实际仍失败；不会混成通过 |

每行显示前次与本次的实际状态、共享测试文件核对和本轮执行状态，详情显示两个 SHA-256。摘要的实际失败／受阻／未执行数量独立统计，测试文件变化不会遮住这些状态。指纹按整个文件计算：编辑同文件的其他测试，也会标记该文件的共同目标发生变化。原先未执行或受阻、本轮通过时单列“本轮通过，前次未定／未执行”，不认作从已观察失败恢复。

基线、记录的 Python／发行包环境和每版时限分别提示相同、不同或未知。旧记录缺少可选信息时显示未知。正常修复业务源码会更新工作区快照，比较会说明这项输入变化，继续显示实际结果。

桌面对比、复制摘要及 CLI `project compare EARLIER LATER --output comparison.json` 使用同一套判断。比较 JSON 使用 schema 3，原两路径 CLI 入口和可读取的旧报告继续保留。比较是对历史证据的描述，不重新执行或替代正式验收。

## 来源移动、丢失或不一致

自动进展与“查看逐项变化”按保存的会话 ID、运行 ID 和报告文件 SHA-256 核对身份，同时执行原有证据校验。目录、标题或“最近一次”均不作为身份依据。

来源目录移动或丢失时，点击“重新定位来源报告…”选择原报告的新位置。通过核对后只保存本机定位偏好，不改写任一来源报告。选择同一会话的另一份报告、报告文件有变化，或日志／源码等证据校验失败时，停止比较并显示原因。原报告缺失时可先找回完整原报告或其证据包，再重新定位；不会生成猜测性的比较结果。

## 把多轮结果交给其他人

在最后一轮结果页选择“导出与证据 → 导出本次与复查来源 ZIP…”。它包含本次运行与报告明确引用的全部来源，逐份校验会话 ID、运行 ID、报告指纹及执行证据。来源丢失时，重新定位后再导出，也可选择仅导出本次运行。完整复查链最多 50 轮、报告 JSON 合计 64 MiB；ZIP 上限为 20,000 个条目、250 MiB。

对方从“报告与证据 → 导入证据 ZIP…”打开后，可直接查看复查进展和处理记录，来源按包内路径查找。导入不会启动测试；重放须明确发起并选择可用的本机环境。包里包含报告、冻结源码和运行日志。本机处理说明及未保存的编辑留在本机。单份报告 ZIP 仍可照常导出和导入。

命令行使用 `reprolab project pack REPORT --include-sources --output history.zip`。来源已移动时，可重复提供 `--source-directory DIR`。用 `reprolab project unpack history.zip NEW_DIR` 校验并导入，然后用 `reprolab project history NEW_DIR` 查看处理记录。导入后的报告可正常校验和明确重放。

## 购物车验收场景

新建购物车示例会附带 `recheck-scenarios/`，包含三个独立补丁、使用说明和 `expected.json`。每个文件修改场景从同一份初始示例开始，建议分别创建示例，并明确发起发现和执行测试。

| 场景 | 操作 | 预期检查点 |
| --- | --- | --- |
| 修复源码 | 保留 `test_money_display` 断言，应用 `fix-money-display.patch` | 金额显示从新增失败转两版通过；测试文件相同，同一检查转为通过计 1 |
| 放宽同名测试 | 保留显示错误，应用 `change-money-test.patch`，只检查以 `12` 开头 | 显示本轮实际两版通过；共享测试文件变化，转为通过计 0；同文件共同项都标记变化 |
| 改名 | 应用 `rename-money-test.patch` | 原 ID 本次未找到且可查看；确认前不自动勾选，连续刷新和重开仍保留；只采用其余 8 项后原 ID 列为未复查 |
| 只查需处理项 | 修复源码后从来源报告选择需处理的 3 项 | 原来的另外 6 项单列未复查，原报告可打开 |
| 主动清空 | 清空、重开、重新发现或刷新 | 范围仍为 0，正式运行提示选择 1–2000 项 |
| 来源错误 | 移动报告、选择另一份同名报告、或只在一次性副本中修改日志 | 分别重新定位、身份不符、证据不一致；后两者停止比较 |

这些是可复核的预期，实际执行记录与 `expected.json` 分别保存。当前定向测试和桌面检查范围见[验证与发布状态](release-readiness.md)。


## 一次操作完成复查（0.19.0a2）

“复查修改”菜单优先提供“复查并运行全部”和“复查并运行需处理项”。入口本身就是明确执行指令，依次完成固定当前修改、实际发现测试、核对原 ID 和两版执行。复查直接复用来源报告中已校验的基线快照。

若测试缺失、发现不完整、原测试文件、pytest 配置、fixture、测试辅助材料或插件配置改变，会保留已经准备的新会话，转到测试范围供你核对，再自行点击运行。中途取消可保留已保存材料；没有完成的测试不会算通过。原来的“仅准备…”入口继续用于分步操作。

CLI 使用同一流程：

```sh
reprolab project recheck /path/to/source-report \
  --sessions /path/to/sessions --output /path/to/reports \
  --scope all --python /path/to/project-env/bin/python
```

`--scope attention` 仅沿用来源报告的失败／受阻项。省略 `--timeout` 时沿用来源报告记录的限时，旧报告无可用记录时使用 120 秒。显式指定 `--timeout` 可改用本次限时。返回 `needs_review` 时退出码为 2，`state.directory` 指向可继续的会话；已经执行时沿用项目运行的退出码。

比较 JSON 为 schema 3，保留 `state_change` 描述实际结果。只有测试文件、固定基线、已记录环境、时限、选择顺序、测试辅助材料及 ReproLab 版本均可核对为相同，才计入 `same_check_resolved`。条件变化或未知时使用 `conditions_changed`／`conditions_unknown`，本轮实际通过仍显示。

辅助材料依据已校验的源码证据，保守比较测试目录的其他文件、上级 conftest／配置和已声明本地插件，不执行项目代码。详情列出变化文件。未追踪的动态依赖、环境变量和外部服务不在此完整性承诺中。仅复查失败项改变了选择范围，会明确提示复核；正式确认具体修复仍使用严格案例。


## 只复查一个现象组或明确子集

0.19.0a4 的结果页支持“复查本组”，范围来自这份来源报告，搜索隐藏的成员也包含在按钮标明的数量中。CLI 可重复使用 `--test` 指定相同子集，保留来源顺序；与 attention 范围互斥。来源记录的 selection_mode 为 selected。未复查项仍单列，详细说明见[失败归类](failure-triage.md)。


## 多轮处理记录（0.19.0a7）

在项目结果页点击“处理记录”。“各轮记录”沿报告中保存的精确复查来源排列，可以查看本轮结果、与上一来源的比较，以及两轮候选快照中的文件内容／可用权限变化。选择一轮后可打开其原报告或重新核对并比较两轮。

“测试去向”汇总已核对区间内出现过的测试。即使某项在连续多轮中都没有再选择，它仍标为“本轮未复查”，显示最近一次保存的状态和来源轮次。历史通过不表示当前通过，历史失败也不证明当前代码仍失败。对本轮已选测试，会与最近一次可用观察比较；测试内容或检查条件变化继续单列，不能混成严格修复验收。

在有明确报告显示、且该报告属于当前固定会话时，普通“刷新当前工作区”也会核对并保存此报告的来源关联，沿用当前勾选／继承选择。未显示报告时不按时间猜测上一轮。旧报告仅展示已经保存的关系；同会话其他运行和并行分支不会自动并入。

### 本机处理说明

每轮可填写最多 4000 个字符并点击“保存本轮说明”。说明按报告身份保存在应用工作目录的 `run-notes` 中，不改写报告、源码或验收结论。重开后会恢复；其他窗口已改变说明时须重新载入，当前草稿保留。

复制摘要和导出 JSON 包含已保存说明，不包含未保存草稿。切换轮次、重新核对或关闭窗口时，可以取消操作以继续编辑。损坏的本机说明单独提示，不遮住有效执行记录。

### 来源缺失与读取范围

默认读取最多 20 轮，可在达到上限时继续读取至 50 轮。累计报告 JSON 上限 64 MiB，已核对测试标识范围上限 10000 项／8 MiB。源码与日志仍按原有证据规则逐份校验。

来源丢失、身份不符、证据不一致、重复引用或达到上限时，窗口会说明停止位置；统计只覆盖已核对区间，不能把未读取的范围视为已解决。选择“重新定位来源”后仍需匹配会话 ID、运行 ID 和报告指纹，并核对全部执行证据。定位偏好只存在本机。

### CLI 与导出

```sh
reprolab project history /path/to/current-report --output /path/to/history.json
reprolab project history /path/to/current-report \
  --source-directory /path/to/moved-source-report \
  --notes /path/to/run-notes --max-rounds 50
```

`--source-directory` 可重复，提供明确的移动后来源目录，不按标题匹配。退出码 0 表示已读到已记录来源的起点，2 表示来源链只读取了部分；均不代表项目测试通过。

处理记录 JSON 是汇总，包含报告身份、结果变化、跨轮未复查项和已保存本机说明，不包含完整源码与日志。需要交付或重放时，另行导出相关各轮的证据 ZIP；导出汇总须选择所有来源报告目录之外的新文件。

## 运行变量与复查

变量声明变化会与插件／导入配置变化一起停下供核对。历史比较记录普通值和本机名称；本机值不保存，跨轮一致性保持未知，因此实际转绿仍需复核，不据此计入同条件已解决。重放需重新提供本机值，详见[运行变量](runtime-variables.md)。
