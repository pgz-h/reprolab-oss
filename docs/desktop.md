# ReproLab 桌面端（0.18.0a3.dev1 未发布验证版）

本轮本地交付为 `.app` 与应用 ZIP。0.19.0a2 的验证范围见[验证与发布状态](release-readiness.md)，构建与功能验收分别记录。

0.18.0a2 增加“刷新当前工作区”：修改原项目后另存新快照，沿用固定基线和当前勾选，重新发现后逐项核对缺失目标。原会话与报告保留；旧会话上的重跑仍使用旧源码。选择清单与命名方案提供完整核对窗口，可搜索和复制缺失 ID，明确采用后再替换勾选。

## 从失败结果继续修复

在“项目工作台 → 回归结果”选中失败，详情直接提供“准备修复说明”和“验收当前修复”。前者只整理报告保存的历史证据为可编辑、复制、导出的本地全文；后者先校验实际故障来源，再冻结当前工作区。确认问题、行为与稳定异常片段后保存正式案例，转到单项验收由用户明确开始。原报告基线只作背景，故障版采用实际失败的变更后快照。测试变化会显示，默认仍采用原完整检查。

“更多操作”归并固定快照重跑、复制／CSV、测试预览、重新定位当前报告与重开修复准备；“导出与证据”归并证据目录、ZIP、固定快照重放和复查来源定位。具体步骤、CLI、错误恢复与验收场景见[失败修复指南](failure-repair.md)。

## 项目回归工作台

从“概览”选择“检查一次项目改动”，或点击“项目工作台”页签，一次完成项目输入冻结、改动浏览、实际测试发现、多选执行及逐项结果查看。最多选择 2000 个精确测试目标，前后版本各运行一个 pytest 进程。项目会话可重开，支持重跑选中或需处理项、报告 ZIP 导出/校验导入和明确重放。

工作台提示当前下一步；项目环境单独选择，常见环境仅列出路径，不自动切换或启动。标题与问题说明可按需展开。小窗口输入区可以滚动。测试发现失败会展开日志；完整操作错误可复制。结果默认定位新增失败，“定位需处理项”可集中查看新增失败、原有失败和受阻项。

从工作台进入 AI 计划时，使用同一份已冻结源码。改变 Python 不必重新复制源码，重新发现测试后即可运行。原案例验收、测试草稿、报告与设置页面继续保留。完整操作见 [项目工作台](project-workbench.md)。

## 打开应用，完成一次验收

1. 打开发行包中的 ReproLab.app。也可以先打开 DMG，再把应用拖到你选择的本地目录。
2. 初次使用可以在“概览”直接点击“运行内置示例”，使用应用 Python 完成教学验收；你原先选择的项目环境会保留。也可在“案例验收”选择已有案例，内置 humanize 历史案例可直接运行。
3. Python 一栏留空表示使用应用内置的 Python 和 pytest，不需要手工创建环境。项目依赖额外包时，点击“选择 Python…”选择项目虚拟环境中的 bin/python；不会自动安装依赖。
4. 点击“开始验收”。旧版、新版依次在临时副本中运行；窗口保持可操作。运行中可取消，正常关闭窗口也会请求取消并等待清理。
5. 查看两版结果和中文结论，点击“打开完整报告”或“打开证据目录”。

“修复验证通过”要求旧版出现预先声明的故障、新版同一测试通过。每个案例最终只选中一个测试。环境就绪、草稿已生成、证据一致，都不等于修复验证通过。

两版运行结束、开始提交结果后，取消按钮会禁用；此时已经完成测试，不再接受取消请求。已取消任务不保存新的成功报告；强制结束应用后，下次启动将原来的运行中记录标为未完成。不完整输出目录可能保留，不能用作已完成报告。

## 看懂结果并继续处理

点击“开始验收”后会自动预检；配置或环境元数据有关键问题时不执行测试。结果区用真实阶段记录解释原因，并显示下一步建议。例如旧版预期报错会显示“已复现声明的故障”，缺模块会提示核对环境和项目依赖，缺少工作进程记录时不会声称没有测试。

新报告记录环境版本。再次验收或从旧批次重跑时提示环境变化；历史没有环境记录时明确无法比较。清单不是依赖锁，也不检查包内文件内容。

在批次结果或报告页选择旧批次，可“重跑未通过项”或“继续未完成项”。新清单支持选择环境，确认开始后生成独立批次；旧汇总与证据保留。具体边界及CLI用法见 [预检、诊断与重跑](diagnostics-and-retry.md)。

## 在界面里创建自己的案例

点击“新建验收案例…”，选择本地 Git 仓库。读取提交后，从列表选择修复前和修复后的版本；提交说明和日期方便辨认，也可以输入更早的提交或标签。

点击读取测试，从修复后版本的静态列表选择一个测试，填写旧版应该出现的异常类型和消息片段；参数化测试需在目标中补全具体参数标识。选择已有项目环境后，保存到案例目录。向导所选环境会同步到主窗口，后续单项和批量使用当前显示的环境。

保存固定两个完整提交，不切换分支、不覆盖原仓库、不运行测试。保存后自动选中新案例，再由你点击“开始验收”。已有文件不会覆盖。窗口空间不足时可以滚动表单，底部保存/取消按钮始终可见。

## 批量处理已有案例

在案例列表勾选 1–50 个案例，点击“批量验收”。打开的清单会显示本批次的环境，再点击“开始批次”。

案例依次执行，每项仍只运行一个测试；某项错误不会阻断后续案例。取消会停止当前测试，保留已经完成的真实结果，尚未完成/未运行项不能算通过。结束后打开批次总览，可进入每项报告。批次总览也会列在“报告与证据”页。

批量统一使用当前选定的 Python 环境；依赖环境不同的项目应分批运行。“勾选可见项”只勾选当前搜索/筛选后可见的案例；已勾选项在改变搜索后仍会保留，总数显示在批量按钮上，开始前可在批次清单核对。

案例、草稿、报告支持搜索；案例还能按待验收、通过、需要查看、历史或取消筛选。没有可运行的选中案例时，验收按钮禁用。

## 已有项目与数据

“选择案例文件…”可以添加现有 JSON；文件仍保留在原位置，不复制或改写原案例。设置和最近选择会在退出后保存。案例、测试、快照源码或 Git 提交变化后，刷新列表会把旧结果标为历史；依赖环境变化不在指纹检查范围内，需要实际重跑。

在这台已有工作区的 Mac 上，自动使用：

- 案例：~/开源项目研究/work/reprolab/cases
- 草稿：~/开源项目研究/work/reprolab/drafts
- 报告：~/开源项目研究/outputs/reprolab/reports
- 导入：~/开源项目研究/outputs/reprolab/imported
- 桌面设置和活动记录：~/开源项目研究/work/reprolab/desktop

其他安装默认把工作材料和设置放在 ~/Library/Application Support/ReproLab，报告放在 ~/Documents/ReproLab。目录均可在设置页选择；安装包不包含本机案例、用户模型配置、Key 或开发日志。内置教学案例与 humanize 单模块历史样例是项目自带的可公开示例。

## 草稿与模型

草稿页查看问题、完整待发送提示词、测试草稿、检查说明和假设，支持离线恢复、导入模型 JSON 和审阅后验收。

模型配置保存在本机 JSON 中。连接窗口及 AI 入口提供按模型保存的思考强度；自定义网关可按服务文档选择兼容方式，发送前预览显示当前参数。具体支持范围见[模型连接与思考设置](model-connections.md)。设置页支持选择已有配置，也可点击“连接模型…”填写接口地址、协议和 API Key，再“获取可用模型”并点选。模型目录支持搜索、手动添加和移除，已保存服务可在窗口顶部切换。Key 输入框以密码形式显示，保存时创建仅当前用户可读写的新配置。点击“准备新草稿…”可选择仓库与两个提交，填写问题，自动选择或手工勾选最多 12 个上下文文件，然后离线准备。准备结束自动选中新草稿；如选择了其他保存目录，当前草稿目录也会同步切换，原目录文件保留不动。准备不会调用模型、生成测试或运行代码。

如果修改连接的域名、端口或 HTTP/HTTPS 方式，仍要使用当前 Key 时需在窗口明确勾选；也可直接填写新 Key 或选择新的 Key 环境变量。新凭据绑定输入时的服务地址，之后切换到其他服务仍需重新选择或确认。同一服务内仅修改路径不需要凭据确认。更换服务后，获取新模型目录会替换原连接的目录；若获取失败，窗口会提示仍显示的是先前连接的目录，需明确添加旧模型 ID 才能在新服务测试或保存。

点击“预览并生成…”后，窗口显示服务地址、协议、模型和完整提示词。勾选同意并点击“发送并生成草稿”才请求模型。预览后上下文或配置改变会要求重新预览。模型响应不会自动执行；草稿生成和验收是两个独立动作。

本轮开发只用本地模拟服务验证发送流程，不代表真实服务稳定性或复杂项目生成质量。应用不自带 API 账号。

## 报告与证据

报告页显示所选目录下最近报告（最多 500 份，扫描三层，不进入证据快照）。

- “检查证据”：核对文件内容及新报告记录的源码普通文件权限，不执行代码；旧报告会提示未记录的权限无法核对。
- “导出证据 ZIP…”：复用已有证据打包器，不覆盖已有 ZIP。
- “导入证据 ZIP…”：校验后存入新的独立目录，展示原结论和保存位置。
- “审阅后重放”：只有明确点击才运行刚导入的代码。

新导出的证据包保留普通文件的读写执行权限，使用格式 2 和 schema 4 报告；本版可导入旧格式，旧版 ReproLab 则需升级才能使用新包或报告。新报告的回放会在执行前核对源码、普通文件权限和测试是否与保存时一致。一致性校验不是作者身份认证。导入报告中的通过是历史记录，不能代替本机重放结论。

## 使用边界

macOS 桌面开发预览面向 Apple 芯片（arm64），打包组件要求 macOS 14 或以上。Windows x64 与 macOS 共用版本和核心流程，构建与原生验收见[Windows 指南](windows.md)。

应用带有打包工具生成的本地 ad-hoc 签名，用于 Apple 芯片装载要求；没有 Apple Developer ID 身份签名，也没有 Apple 公证。下载到其他机器可能被 Gatekeeper 提示，不能承诺无提示启动。如果系统拦截，请先核对下载来源和校验值，再按 macOS 提供的“隐私与安全性”流程处理；不要关闭系统安全机制。

只运行你信任的本地代码。进程隔离不是安全沙箱，代码仍可能访问文件和网络。报告与测试日志可能包含项目数据，分享前需检查。

内置环境提供 Python、pytest 和应用所需标准库模块，不是通用开发环境；有项目依赖、动态标准库需求或自启动 Python 子程序的项目应选择完整的外部 Python 环境。打包后的 sys.executable 是应用分派器，不支持任意 Python -c/-m 参数。

桌面没有改写验收标准：项目测试仍使用 after 的同一份测试覆盖两个临时副本，不改原仓库及保存的原始快照；addopts 和自动插件发现仍禁用。已有 CLI 命令全部保留。桌面已接入项目测试案例创建、静态测试选择、离线草稿准备和批量验收；独立快照案例的文件编辑仍可使用现有 CLI/JSON。

## 开发和打包

开发启动可使用安装了桌面可选依赖的环境：

    python -m pip install -e '.[desktop]'
    reprolab-desktop

打包只在 Mac arm64 上执行；构建环境和临时目录应在源码仓库之外。具体命令、固定依赖和实机 smoke 验证见 [桌面构建说明](../packaging/README.md)。不需要在用户启动应用时执行这些命令。

## 直接验收尚未提交的修复

新建案例时勾选“验收当前未提交的修改”，选择Git基线和测试，保存时冻结代码。参数化测试可点击“列出实际测试与参数”后点选具体实例。实际收集会加载可信项目；保存及静态读取不执行代码。完整流程见 [当前工作区验收](workspace.md)。

## 先识别旧版故障

新建案例时，改动相关的测试会优先排列。选择测试后可试运行旧版，查看实际错误并点击“确认并采用此故障”，再保存案例。手工异常字段在可展开项中调整。正式验收使用当时固定的代码重新运行两版。详细流程见 [故障识别引导](failure-probe.md)。

## AI项目验收与模型连接

案例验收页的“AI项目验收”可从问题描述生成一组检查。模型连接在设置页填写，环境可在计划窗口检查和准备。报告页提供AI解读入口，每次发送前展示实际内容。操作见 [AI项目验收助手](ai-project-acceptance.md)。

生成后，审阅区显示测试目标及旧版预声明异常。点击“编辑检查 / 另存审阅版本…”可逐项修改代码、已有项目测试目标、用途、预期行为、假设和故障条件，也可添加或移除检查。保存后在原计划旁创建新的独立目录，并切换到新版本；原计划和报告保留，新版本需要重新开始实际验收。

模型完整响应已保存、计划生成或保存未完成时，“恢复已保存响应”会立即启用并保留错误说明，也可以之后重新打开计划再恢复。恢复只读匹配的本地响应，不再次调用模型。中断留下的未完成文件会保留在计划目录下的 `.incomplete-*` 目录；已完成计划不会被覆盖。旧版本没有来源检查点的响应需明确导入。

dev3 可在已保存计划内选中一项，点击“试运行所选检查的旧版”。这会实际执行可信项目的旧版测试，使用独立副本和所选 Python，只运行同一项检查的旧版。结果区显示实际异常、日志节选、测试标识、Python 及完整材料位置。可取消，关闭窗口时会等待工作进程清理。

只有可用的目标修复故障才能采用：先核对观察是否对应目标问题，勾选确认，再将条件带入编辑窗口。此时仍可修改稳定消息片段和测试，审阅后另存独立版本。原计划保留，正式验收重新运行前后两版。切换检查、Python 或计划会清除观察；已有记录可通过“打开旧版观察记录…”重新查看匹配的来源。

## 报告驱动复查（当前未发布工作区）

项目结果页区分“固定快照：重跑…”与“用当前工作区复查”。后者可带入报告全部实际选择或仅需处理项，并保存具体运行身份。新报告通过“与上次比较”查看结果与条件变化；移动的来源须重新定位核对，证据不一致会停止。完整说明见[报告复查](report-recheck.md)。
