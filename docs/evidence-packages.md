# 检查、打包与导入验收证据

v0.8 将一份已保存的单案例报告整理为可搬动的 ZIP：报告、日志、测试、两个版本的源码快照，以及文件校验清单。所有操作只在本机进行，不调用模型、不上传文件，不运行包里的测试或项目代码。

## 1. 检查已有报告

    python -m reprolab report check /path/to/reports/RUN-ID
    python -m reprolab report check /path/to/reports/RUN-ID --json

检查测试 SHA-256、两份源码树的内容指纹（包含空目录）、回放案例中的故障条件、测试目标、来源、起草说明及记录的解释器是否与 report.json 一致。新生成的 schema 4 报告还记录并检查源码普通文件的读、写和执行权限；旧报告没有这些记录时，检查结果会说明权限无法核对。旧工作区、试运行或 AI 计划没有记录原始权限时，新报告也会说明这一限制。

返回 consistent（证据一致，退出 0）或 inconsistent（不一致，退出 2），并列出发现的问题。JSON 的 recorded_verdict 是原报告记录的 verified/not_reproduced/still_failing/inconclusive，与本次一致性结果分开。

**证据一致不等于修复通过。** 一个记录为 still_failing 的报告也可以具有一致、完整的证据，也应该能交给别人核对。检查不会重新执行测试，不证明来源身份或根因，也不保证另一个环境中的结果。

包含 persistence 记录的报告还会核对 HTML、日志和事件文件保存时的内容指纹；更早的报告只检查这些文件存在。指纹不是数字签名，也无法证明文件没有被连同报告记录一起改写。

## 2. 生成证据包

    python -m reprolab report pack /path/to/reports/RUN-ID --output /path/to/bundles/case.zip

pack 自动先执行一致性检查，不需要你为了打包先手动 check。它只选取以下文件，不递归复制整个报告父目录：

```text
case.zip
  report.html / report.json
  before.log / after.log
  before.events.json / after.events.json
  evidence/
    case.json / regression.py
    before/ / after/
  reprolab-bundle.json       文件路径、大小、类型和 SHA-256 清单
  README_REPLAY.txt          导入后如何重放
```

不加入放在报告根目录的其他文件，例如临时 ai.local.json。源码快照继续沿用原有 .git、环境、缓存、构建目录和 .env* 排除规则。空目录会保留；新版证据包保留普通文件的读、写、执行权限位，避免导入后脚本权限发生变化。目录权限、所有者、ACL、扩展属性和特殊权限位不属于此保证。

包包含源码、日志和项目数据，不是脱敏版本。模型配置文件不在打包清单中，但源文件或测试输出本身仍可能包含敏感数据；决定分享前应查看包内容。ReproLab 不会替你上传或发送文件。

已有 ZIP 不会被覆盖。输出 ZIP 必须放在原报告目录外。若检查失败或打包过程中文件内容发生变化，不发布半成品 ZIP。

新版生成的证据包使用格式版本 2，报告使用 schema 4；当前代码也能导入旧版格式 1 和 schema 3 报告，但 v0.17.1 及更早版本不支持新的证据包和报告，需要更新后再使用。旧包沿用其生成时的权限规范，无法补回之前未保存的原始权限。

## 3. 导入到新目录

    python -m reprolab report unpack /path/to/bundles/case.zip /path/to/imported/case

导入会检查：

- 包格式、版本和清单是否有效，文件列表是否完全匹配；
- 路径是否是包内规范相对路径，有无越界、重复项、符号链接或特殊文件；
- 是否超过条目/解压总大小限制，各文件内容是否匹配清单；
- 展开后的测试、源码和回放案例是否仍与报告一致。

检查与展开先发生在目标父目录下的临时目录；全部成功后才形成指定目标目录。已有目录（包括空目录）不会被覆盖；失败时清理本次临时内容。不会执行安装脚本、导入 Python 项目或运行测试。

直接用普通解压软件也能查看标准 ZIP 内容，但只有 report unpack 会执行上述 ReproLab 清单与证据检查。

## 4. 审阅可信后重放

先安装 ReproLab，准备 Python >=3.11、pytest >=8,<10 和案例依赖，再执行：

    python -m reprolab verify /path/to/imported/case/evidence/case.json --python /path/to/env/bin/python --output /path/to/new-reports

原始解释器路径保留在证据中；换电脑后用 --python 选择现有环境。证据包不包含虚拟环境、不锁定或自动安装依赖。报告内原来的绝对机器路径仍作为原记录保留，导入后的实际入口是命令返回的 report 和 case 路径。

重放会真正执行两个版本和同一份测试，生成新的独立报告。新报告的回放案例在执行前会核对保存的源码内容、普通文件权限和测试指纹，发现变化时停止；旧报告没有这项绑定，重放前应先检查并审阅。源码快照不再依赖原 Git 仓库。仅运行你审阅并信任的代码；子进程不是安全沙箱。

## 范围和限制

- 支持 schema_version=3 和 4 的单案例报告，包括旧版本生成的兼容报告。批次总览请分别导出每个案例。
- 最多 12000 个归档条目；ZIP 文件和解压后的总内容（含清单）各不超过 250 MiB。源快照仍适用每版 5000 条目/100 MiB 限制。
- 不支持加密 ZIP、符号链接、特殊文件、包含 `..`/反斜线/冒号/控制字符或不规范片段的归档路径。
- 清单不是身份认证。攻击者若同时改写文件和清单，不能靠本地 SHA-256 证明来源可信。
- 不改变既有验收结论，不修复代码，不触发模型请求或自动发布。

## 当前本机目录

证据包建议放在 `/path/to/reprolab-outputs/bundles`；导入目录放在 `outputs/reprolab/imported`。安装后可直接使用 `reprolab report check/pack/unpack`。


0.19.0a5 的项目报告增加每版 `*.progress.jsonl` 逐项事件，纳入原有内容校验和 ZIP 交付。新报告的进度摘要与中断观察会从原始事件重新核对；序号、选择来源或最终事件不一致不能产生通过结论。中断时仅忽略最后一条尚未写完的行，其他格式错误会明确显示。旧报告没有这些字段时继续按原有事件核对，不补造实时进度。含中断观察的新报告应使用 0.19.0a5 或更新版本读取。

## 可重放的范围

证据一致性、能够重新执行、以及多次得到相同结果是三个不同的问题。源码和测试已固定，依赖元数据用于比较；操作系统、系统库、服务数据、网络响应、时间和随机性仍可能变化。环境不匹配时应记录差异并生成新的执行证据，不能把旧报告的通过直接作为当前结果。详见 [CLI 与报告契约](cli-contract.md)。
