# 第一次使用 ReproLab

桌面左侧依次提供“概览”“项目检查”“修复验收”“报告与证据”，AI 与设置位于辅助工具区。项目检查只在第一步显示仓库、版本和环境。选择测试后直接进入结果页，长详情在右侧独立滚动。


ReproLab 用同一份测试对比改动前后的代码，并保存实际结果。已有测试就能使用，不需要模型账号；AI 可以帮助准备测试，结论来自实际执行。

## 使用 CLI 快速了解

已安装 CLI 后可运行 `reprolab history --output /tmp/reprolab-history`，查看 humanize 已知历史修复的两版结果；来源与范围见[真实历史案例](history-case.md)。它无需模型账号，也不下载或安装被测项目。自己的项目接入和自动化见 [CLI 与 CI](cli-contract.md)。

## 先体验一次完整验收

1. 打开 ReproLab.app，进入“概览”。
2. 点击“运行内置示例”。不需要选择项目、配置模型或创建 Python 环境。示例使用应用自带环境，你原先选择的项目环境会保留。
3. 查看结果：旧版导出中文文件名时出现预先声明的错误，新版通过同一测试，显示“修复验证通过”。
4. 点击“打开完整报告”，查看测试、两版日志和保存的源码证据。

这是人为构造的教学案例，用于理解操作流程。它不能替代你自己项目的测试。

如果想体验项目工作台，点击“创建项目示例”。它会在应用工作目录中创建独立购物车 Git 项目并冻结输入，不自动执行测试。随后点击“发现测试”和“运行所选项”，可对照项目 README 中声明的预期结果，理解两版通过、改善、新增失败、原有失败和受阻。

## 从失败继续处理

已有项目报告时，选中失败即可在详情准备本地修复说明。填写问题与期望行为后预览自动更新，审阅后直接复制或导出交给 AI／开发者；手工编辑与表单冲突时会先保留内容并暂停交付。编辑自动保存为本机草稿，重开同一失败项可恢复；更多操作提供草稿列表。修改业务源码后，从原失败准备“验收当前修复”，核对真正失败的原快照与新候选、原测试及稳定异常条件，保存后再到单项验收明确执行。之后用项目复查核对相关回归。完整步骤见[失败修复指南](failure-repair.md)；历史验证范围见[验证与发布状态](release-readiness.md)。

## 检查自己的项目改动

适用条件：可信本地 Git 仓库，至少有一次提交，已经有 pytest 测试。

1. 返回“概览”，选择“检查一次项目改动”。
2. 选择项目文件夹。默认用最近一次提交（HEAD）作为改动前版本，与当前未提交工作区比较；如果修复已经提交，选择实际的改动前后提交。
3. 选择已经安装项目依赖的 Python。读取仓库后，下拉列表会列出常见虚拟环境的路径，供你选择；“检查环境”窗口也会直接列出原项目环境，冻结后仍可选择。不会自动启动或切换。没有合适环境时，点击“检查环境…”选择测试／开发依赖组，筛选缺失依赖，或预览新环境的准备方式；插件页可添加插件、预览并应用原项目配置、撤销修改，并直接衔接刷新工作区；“运行差异”说明实际参数与环境继承规则。详见[项目环境接入](project-environment.md)。
4. 点击“准备并发现测试”。工具会固定两版源码并执行可信项目的收集代码，随后进入测试范围；不会运行测试主体。需要先审阅代码差异时，也可选择“仅冻结版本”，之后单独发现。
5. 根据改动和推荐原因核对勾选测试，再点击“运行所选 N 项”。发现遇到错误可直接“检查项目环境”，选择原项目环境并检查后点击“使用环境并重新发现”，或直接“重试发现测试”；修改原项目后可“更新源码并发现”，沿用基线另存快照并核对范围。
6. 查看两版结果。需要处理的结果可按现象组筛选，查看建议、复制本组诊断；修改后可直接“复查本组”。具体测试仍可查看异常和日志。

标题和问题说明是可选项，可以展开填写。搜索只影响显示，隐藏的勾选项仍会运行，界面会提示数量。只想运行搜索结果时，先清空勾选，再选中可见项。

工作台可按目录或文件筛选，也可以直接点击“仅选可见”替换当前勾选。“选择操作”提供反选可见项、复制 ID、导入和导出。导入先显示完整核对窗口，支持查看和复制缺失 ID；明确采用可用项才更改勾选，不自动执行。

关闭前会记住勾选、搜索、文件范围、筛选和限时。下次从开始页点击“继续上次项目”，匹配固定输入与发现环境后恢复；你主动清空的勾选也会保留。

结果页的“更多操作”可复制当前筛选的摘要，或导出包含两版状态、异常和耗时的 CSV。它们方便整理问题记录，完整执行证据继续保留在原报告中。

如果经常检查同一批测试，可以把当前勾选保存成命名方案，之后在同一仓库的新会话中复用。结果详情会按实际异常和阶段给出下一步建议，也可以预览报告保存的测试代码。

反复重跑后，可以在“运行记录”中同时选中两次记录，比较哪些共同目标的结果变化了、哪些只是本次没有选中。仅一次运行选择的项目会单独列出，不会被算成已经修好。

修改了原项目的源码后，点击“刷新当前工作区”创建新会话，再发现和运行。刷新沿用原固定基线并带入当前勾选，原会话和报告保留；有测试改名或消失时先核对，不自动补选。直接在旧会话重跑仍使用旧快照；只调整运行环境时才适合直接重跑或重新发现。

## 结果没有通过时

| 情况 | 下一步 |
| --- | --- |
| 测试发现失败、缺少模块 | 查看自动展开的日志，检查项目环境，更换 Python 后重新发现；固定源码保留 |
| 新增失败 | 查看两版异常和日志；修改源码后刷新工作区，再发现、核对和运行 |
| 两版均失败 | 核对原有问题和测试预期，不能把它当作本次新增失败或回归通过 |
| 跳过、fixture 错误、超时等受阻 | 处理对应原因后重跑；受阻不计入通过 |
| 已取消 | 已完成记录保留，未完成项不算通过；可以继续选择并重新运行 |

发现清单有收集错误或被截断时，不自动勾选测试；先处理问题，或明确选择当前可用项。空范围会提示检查 `testpaths` 和测试命名；超时可调整上方时限并重试。更新源码会创建新会话，直接重试发现仍使用原快照，旧材料保留。

## 选择其他入口

- **确认一个具体问题修好了**：已经知道旧版应该出现的故障，用“案例验收”预先声明故障条件，再检查新版。项目回归通过只覆盖所选测试，不等同于正式验收了一个目标修复。
- **让 AI 帮我准备检查**：准备改动材料和预期行为，审阅发送内容后才请求已配置的模型。审阅生成的检查，再实际执行。
- **查看或接收执行证据**：查看报告、校验证据并导出 ZIP；导入只检查保存材料，审阅后明确重放才执行代码。

源码和日志可能含项目数据，分享前请检查。测试收集和执行只适用于可信代码；独立进程不是安全沙箱。完整步骤见[项目工作台](project-workbench.md)和[桌面使用说明](desktop.md)。

## 从一份失败报告检查修改后的代码

在项目结果页打开“复查修改”，选择“复查并运行全部”或“复查并运行需处理项”。工具会冻结当前修改、发现并核对原范围，条件满足时直接执行。测试缺失、发现不完整、测试文件、fixture 或 pytest 配置变化时保留新会话供你核对。也可选择“仅准备…”继续逐步操作；新报告会自动核对复查来源，在结果页直接显示修复进展与未复查范围；需要详细依据时点击“查看逐项变化”。这条入口绑定具体运行，普通刷新仍按当前勾选。测试文件变化会单列复核，未重跑项不会算作已解决。步骤和购物车材料见[报告复查](report-recheck.md)。


## 逐项进度与中断记录（0.19.0a5）

运行时显示基线／候选版本、已完成数量、当前完整测试 ID、准备／主体／清理阶段及耗时。5 秒没有新事件时显示距最近事件的时间；这不等于进程失去响应，也不是剩余时间预测。结果列表逐项更新，正式结论在两版执行与证据保存后显示。

超时、取消、运行中 Ctrl-C 或进程异常退出后，已经保存的阶段作为“中断前观察”保留，最后执行位置可在桌面和离线报告查看。未完整结束的版本保持受阻；中断前某项通过不计为正式回归通过。尚无阶段记录不证明测试从未执行。

结果页优先显示与所选项对应的处理入口：导入异常检查环境，准备／清理或中断问题查看日志，测试主体失败准备修复说明，通过项查看测试内容。原有修复验收、诊断复制和证据操作继续保留。

CLI 可在 project collect、run、recheck 和明确执行的 replay 中加入 `--progress`。实时进度写到标准错误，标准输出仍为最终 JSON，便于脚本保存与处理。


## 连续修改后查看处理进展

在当前结果页点击“处理记录”，查看各轮结果和候选文件变化；切到“测试去向”可以筛选本轮未复查项，并找到最近一次观察。处理说明按轮次单独保存，复制／导出时注明为本机说明。来源移动后可重新定位，原报告保留。完整步骤和边界见[报告复查与处理记录](report-recheck.md)。

## 重复接入同一项目

准备或运行后会按仓库路径保存上次使用的 Python 与时限。新建项目并填入相同仓库时，可点击“使用上次环境与时限”；采用设置本身不启动解释器，不自动执行测试。若环境已移动或删除，执行时会明确报错，需要重新选择。

“新建项目”会返回项目配置页并清除旧结果计数；已有会话和报告仍可重开。结果表默认先展示新增失败、受阻及已有失败，执行证据中的原顺序和完整范围保持不变。

## 项目需要环境变量时

在“检查环境 → 运行变量”中填写普通值或声明本机值，预览后应用到原项目，再刷新工作区。只更新本机值时点击“使用本次值”。变量缺失会显示名称并停止；单个快照案例和导入的项目报告重放也支持运行前填写。详细范围见[运行变量指南](runtime-variables.md)。

## 界面帮助与版本

0.19.0a11 起，首页和常规页面只显示功能入口与必要状态。需要了解输入或操作含义时，可悬停相应控件查看提示；实际错误、选择范围提醒和运行状态仍直接显示。版本信息在“设置”页底部。没有上次项目时，首页不显示继续检查卡片。
